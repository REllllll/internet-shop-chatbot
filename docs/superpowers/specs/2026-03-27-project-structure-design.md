# Project Structure Design

**Date:** 2026-03-27
**Project:** Internet Shop Chatbot (Graduation Project)
**Status:** Approved

---

## Overview

A conversational product recommendation chatbot using a monorepo with four Docker services: React frontend, FastAPI backend, n8n workflow engine, and SQLite database. Product data comes from the [Kaggle Amazon Sales Dataset](https://www.kaggle.com/datasets/karkavelrajaj/amazon-sales-dataset) (1,465 products, 16 fields). No user authentication. No persistent user data.

## Conversation Flow

### Phase 1 — Preference Elicitation
1. User sends message → React → `POST /chat` (SSE endpoint on FastAPI)
2. FastAPI appends message to in-memory session and calls Claude API with MCP tools available
3. Claude asks ≤5 targeted clarifying questions (category, budget, use-case, brand preference, etc.)
4. FastAPI streams Claude's text responses back to React via SSE
5. Repeat until Claude determines it has sufficient preferences to recommend

### Phase 2 — Recommendation
1. Claude calls the `get_recommendations` tool with extracted preferences JSON
2. FastAPI POSTs preferences to the n8n webhook (`POST http://n8n:5678/webhook/recommend`)
3. n8n pipeline executes (see below) and returns top-3 products + comparison JSON
4. FastAPI returns the n8n result as the tool response to Claude
5. Claude generates a natural language explanation with trade-off reasoning
6. FastAPI streams the explanation to React; React populates the right-side product panel

## MCP Tools (`backend/app/mcp_tools.py`)

All three tools are defined as Claude tool-use schemas and executed by FastAPI against SQLite.

### `search_products(query: str) → list[Product]`
Full-text search on `product_name` and `about_product` columns. Returns up to 20 matches.

### `filter_products(category?: str, max_price?: float, min_rating?: float) → list[Product]`
SQL `WHERE` clause filter. `category` matches the pipe-separated hierarchy prefix (e.g. `"Computers&Accessories"`).

### `get_recommendations(preferences: PreferencesSchema) → RecommendationResult`
Triggers the n8n recommendation pipeline webhook with the preferences JSON. Returns ranked top-3 products plus a comparison table (feature differences). **This is the primary recommendation entry point — Claude should only call this tool after eliciting sufficient preferences (category + at least one of: budget, use-case, or keywords). `search_products` and `filter_products` are available for ad-hoc lookups mid-conversation (e.g. "do you have any waterproof options?") but are not used for final recommendations.**

`PreferencesSchema`:
```json
{
  "category": "string | null",
  "max_price": "number | null",
  "min_rating": "number | null",
  "keywords": ["string"],
  "use_case": "string | null"
}
```

## n8n Recommendation Pipeline

Triggered by `POST /webhook/recommend`. Five nodes:

1. **Webhook** — receives `PreferencesSchema` JSON from FastAPI
2. **Query Products** — calls `GET http://backend:8000/internal/products?category=…&max_price=…&keywords=…` (an internal FastAPI endpoint, not a public MCP tool). n8n has no native SQLite node, so it delegates data access back to the backend via HTTP.
3. **Rank Products** — scores each product: `score = rating × log(rating_count + 1) × keyword_relevance`
4. **Build Comparison** — selects top 3, generates field-level diff table (price, rating, key features)
5. **Respond** — returns `{ products: [...], comparison: [...] }` JSON to FastAPI

Workflow JSON is exported and committed to `workflows/recommendation-pipeline.json` after each change in the n8n canvas.

## Frontend UI (`frontend/src/`)

**Split-panel layout** (two columns, full viewport height):

- **Left panel** — Chat conversation: user and assistant message bubbles, SSE streaming indicator, text input + send button
- **Right panel** — Product results: empty during elicitation phase, populated with `ProductCard` components and a `ComparisonTable` when recommendations arrive

**Key components:**
- `ChatWindow` — manages SSE connection via `useChat` hook, renders message list
- `MessageBubble` — renders user/assistant messages with streaming support
- `ProductCard` — displays product name, price, rating, discount, and a link to `product_link`
- `ComparisonTable` — side-by-side comparison of top-3 products by key attributes

## Session State

FastAPI stores one `ConversationSession` per browser session (UUID stored in a session cookie):

```python
@dataclass
class ConversationSession:
    session_id: str
    messages: list[dict]          # Claude API message history
    extracted_preferences: dict   # Accumulated from conversation
```

Sessions are **in-memory only** (Python dict keyed by session ID). They are never written to disk. No personal data is retained after the browser session ends. This satisfies the privacy-by-design requirement from the project specification.

## Error Handling

| Failure | Behaviour |
|---------|-----------|
| n8n webhook unreachable | FastAPI falls back to direct SQLite query using `filter_products` tool |
| Claude returns malformed tool call | Retry once with a schema-corrected prompt; surface error message to user on second failure |
| SQLite file missing | Backend startup fails with clear error: "Run `python data/seed.py` first" |
| SSE connection dropped | React `useChat` hook reconnects automatically (max 3 attempts) |

## Setup Commands

```bash
# 1. Seed the database (run on HOST machine — writes to data/products.db in repo root)
python data/seed.py
# docker-compose mounts ./data/products.db into containers at /data/products.db

# 2. Start all services
docker compose -f docker/docker-compose.yml up

# 3. Import n8n workflows
# Open http://localhost:5678 → Settings → Import from file → workflows/*.json

# 4. Open the app
# http://localhost:3000
```

## What This Design Does NOT Include

- User accounts or authentication
- Persistent conversation history across sessions
- Product image rendering (img_link is available but not a priority)
- Real-time product data (dataset is static)
- Deployment / production hosting
